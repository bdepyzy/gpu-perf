The 18-Hour Technical Plan
Blackwell GPU Performance Engineering for Jane Street

12 weeks · 18 hours/day · B200 hardware · targeting Jane Street ML Performance Engineer

What You Need Before Starting

Hardware

  • NVIDIA B200 / GB200-class GPU (compute capability 10.0; verify with nvidia-smi -q)
  • CUDA Toolkit 13.x preferred; 12.8 minimum for B200/CUTLASS
  • Driver compatible with the installed CUDA toolkit
  • ≥ 128 GB system RAM and ≥ 500 GB free NVMe storage

Software to Install

  • ncu / nsys (Nsight Compute & Systems)
  • cuobjdump (from CUDA toolkit)
  • Python 3.12+, torch, nvidia-cutlass-dsl, vllm, sglang
  • vLLM/SGLang source builds, nccl-tests, and optional TensorRT-LLM
  • cutlass and flash-attn for kernel/library comparisons

Accounts & Access

  • GitHub account (for public repos)
  • GPU MODE Discord (community feedback)
  • arXiv account (for paper submission)
  • Personal blog or Substack

Mindset Prep

  • Block social media during HARDS blocks
  • Phone in another room
  • Single-tab discipline
  • Sleep 6h minimum — sleep debt kills SASS reading

Daily Block Structure

Every day uses all four blocks: HARDS, MEAS, READ, and BUILD. Most days are 18 focused hours; Sundays are lighter synthesis/publishing days, but they still preserve the same four-block evidence contract so no day becomes vague.

HARDS Hands-on Hard Stuff 4–6h

Peak-cognition block. Writing CUDA, reading SASS, debugging Nsight Compute, implementing kernels from scratch. No docs reading during this block — that's READ work. Phone away, single tab. If tired, switch to MEAS or BUILD.

MEAS Measurement 3–4h

Microbenchmarks, profiling runs, metric collection. Output is concrete: numbers in a spreadsheet, screenshots saved to notes/YYYY-MM-DD/, annotated Nsight reports. Write a hypothesis before every measurement run.

READ Read & Synthesize 3–4h

PTX ISA, NVIDIA tuning guides, papers, blogs. After each piece: write a ≤200-word summary. If you can't summarize it, you didn't understand it. Summaries become a searchable knowledge base.

BUILD Integration 3–5h

Lower-stakes: extending kernels, refactoring the harness, writing results, polishing artifacts. Every block ends with a git commit. No commit = didn't happen.

⏱ Typical daily flow: 6:00 AM–12:00 AM  |  HARDS → MEAS → lunch → READ → BUILD

Operating Rules

Source ladder

Primary docs first: NVIDIA/CUDA/CUTLASS/CuTe DSL/vLLM/SGLang/NCCL docs and source. Papers second. Blogs and Discord advice are useful only after you can trace the claim to code, docs, or your own measurements.

Measurement contract

Every result row needs: exact GPU, driver, CUDA version, commit hash, clock/power state, input shape, warmup count, repetitions, median/p95, and the Nsight metrics used. If any field is missing, the number is not publishable.

Interview contract

Every week ends with one artifact you can defend on a whiteboard: a diagram, a trace, a SASS excerpt, an ablation table, or a failed experiment with a crisp explanation. The goal is not more activity; it is defensible taste under pressure.

Guidance format

Every checkbox gets a collapsible Why / How note. Treat these as method prompts, not answer keys: they should tell you how to think, what evidence to collect, and which questions to ask before you claim success.

Distributed Systems Track

One-node collective roofline

Measure all-reduce, reduce-scatter, all-gather, broadcast, point-to-point, and all-to-all over 1 KB to multi-GB messages. Compare effective bandwidth to NVLink/PCIe topology from nvidia-smi topo -m. Keep separate curves for latency regime, bandwidth regime, and protocol transition points.

Serving parallelism map

Know what each scheme spends communication on: DDP all-reduces gradients; FSDP/distributed optimizer trades memory for reduce-scatter and all-gather; tensor parallelism inserts collectives inside layers; pipeline parallelism creates bubbles; sequence/context parallelism moves activation shards; MoE expert parallelism adds all-to-all and load balance risk.

Overlap target

The practical distributed question is not "how fast is NCCL?" but "how much communication is exposed on the critical path?" Every distributed profile should report exposed communication time, overlapped communication time, rank skew, and the layer or bucket where overlap breaks.

Cross-Cutting Daily Habits

1. Every kernel gets SASS-dumped before the first run

Write → compile → cuobjdump --dump-sass → skim for obvious problems → run. Prevents 50% of debugging sessions because the bug is visible in SASS before profiling.

2. Every Nsight Compute section gets read — not just the headline

The other 14 sections contain the answers when the headline metric isn't enough: Memory Workload Analysis, Source Counters, Warp State Statistics, Instruction Statistics.

3. Every paper gets a ≤200-word summary committed to your notes repo

Format: title, authors, year, core idea (1 sentence), methodology (1 sentence), result (1 sentence), what it changes about your work (1 sentence). "If I can't compress it, I don't understand it."

4. Every Friday you publish something

A tweet, blog post, repo update, or notebook. By month 3: ~12 public artifacts. Jane Street's hiring team Googles you — the aesthetic is "engineer who works in public."

Common Commands Quick Reference

# Compilation
nvcc -cubin kernel.cu -o kernel.cubin --ptxas-options=-v -lineinfo
nvcc -arch=sm_100 kernel.cu -o kernel           # generic Blackwell
nvcc -arch=sm_100a kernel.cu -o kernel_b100a    # tcgen05/TMEM architecture-accelerated paths

# SASS
cuobjdump --dump-sass kernel.cubin > kernel.sass
cuobjdump --dump-sass kernel.cubin | grep -E 'LDG|STG|HMMA|tcgen05'

# Profiling
ncu --set full --csv -o profile kernel
ncu --section "WarpStateStats" --section "MemoryWorkloadAnalysis" kernel
nsys profile -o trace kernel

# Bandwidth test
ncu --metrics l1tex__data_bank_conflicts_pipe_lsu_mem_shared_op_ld.sum kernel
ncu --metrics lts__t_sector_hit_rate.pct kernel

# CuTe DSL
python -m pip show nvidia-cutlass-dsl
python cute_kernel.py
cuobjdump --dump-sass generated_kernel.cubin | less

# Distributed / topology
nvidia-smi topo -m
NCCL_DEBUG=INFO NCCL_DEBUG_SUBSYS=INIT,GRAPH,COLL torchrun --nproc_per_node=2 train.py
NCCL_TOPO_DUMP_FILE=topo.xml torchrun --nproc_per_node=2 train.py
nsys profile --trace=cuda,nvtx,osrt,cudnn,cublas -o distributed_trace torchrun --nproc_per_node=2 train.py

Key Terms

SASS — Streaming Assembler. The actual machine code that runs on the GPU. Below PTX, architecture-specific.

PTX — Parallel Thread Execution. Virtual ISA that nvcc compiles to. SASS is generated from PTX by ptxas.

TMEM — Tensor Memory. Blackwell-specific on-chip memory that tensor cores write MMA results into. Not registers, not shared memory — its own space.

TMA — Tensor Memory Accelerator. A dedicated hardware unit (Hopper+) that does async bulk copies between global and shared memory independently of warps.

CTA — Cooperative Thread Array. The CUDA term for a thread block. The unit of scheduling on an SM.

SM — Streaming Multiprocessor. The GPU core that executes warps.

Warp — 32 threads executing in lockstep. The fundamental unit of execution.

MFU — Model FLOPS Utilization. Achieved training FLOPS / GPU peak FLOPS for the precision in use.

cuBLAS — NVIDIA's closed-source BLAS library. The performance gold standard for matrix multiply on NVIDIA GPUs.

CUTLASS — NVIDIA's open-source template library for writing high-performance GEMM kernels. The reference implementation for modern GPU matmul.

CuTe — CUTLASS's tensor layout algebra. The abstraction layer for expressing data layouts and tiling strategies.

CuTe DSL — NVIDIA CUTLASS's Python DSL for expressing CUDA kernels with CuTe layouts, tensors, and code generation while staying close enough to inspect generated PTX/SASS.

tcgen05 — Blackwell's tensor-core PTX instruction family. Replaces Hopper's wgmma for Blackwell tensor-core operations.

mbarrier — Memory barrier. Used for synchronization between async operations and warps. Foundation of producer-consumer pipelines.

ILP — Instruction-Level Parallelism. The amount of independent work a thread can issue without waiting.
